## Réponse directe

Les **données sensibles** (clients, santé, secrets, code propriétaire non autorisé) ne doivent pas être collées dans des outils grand public non validés. Une politique simple + formation de l'équipe réduit le risque plus efficacement qu'un interdit vague.

## Règles pragmatiques

- Comptes professionnels validés par l'IT
- Listes « OK / à anonymiser / interdit »
- Pas de secrets API dans les prompts
- Validation humaine sur les sorties critiques

## Lien avec la formation

Un atelier intra doit inclure ce cadre dès le matin — avant les exercices.
